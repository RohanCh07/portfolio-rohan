01 / Overview

An error explained in your editor, the moment it appears.

The extension captures both static lint errors and runtime exceptions while you work, then uses LLM-based retrieval (RAG over a vector database) to explain them. You choose how much help you want: Tutor mode explains why the code broke; Debugger mode proposes a fix.

02 / The problem

An error message tells you what broke, rarely why.

Learners need the reasoning behind an error to stop repeating it; experienced developers just want the fix. Most tools give the same terse message to both, and copying it into a search engine breaks your flow.

  • Terse messages without the reason behind them
  • Leaving the editor to search for answers
  • One kind of help for very different needs

03 / How it works

Catch, retrieve, explain or fix — without leaving the editor.

  1. 01

    Capture

    Collect lint errors and runtime exceptions as they happen.

  2. 02

    Retrieve

    Search a vector database for relevant docs and code context.

  3. 03

    Explain

    An LLM reasons over the error and the retrieved context.

  4. 04

    Tutor or fix

    Tutor mode teaches; Debugger mode proposes a change.

04 / Key decisions

The choices that shaped it.

01

Question

One kind of help, or two?

Choice

Two modes: Tutor and Debugger.

Effect

Beginners learn the cause; experienced users get straight to the fix.

02

Question

How do answers stay grounded?

Choice

Retrieval (RAG) before generation.

Effect

Explanations are based on real documentation and code, not guesses.
