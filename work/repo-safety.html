02 / Overview

Know what a repo will do before you open it.

Repo-Safety reads a folder, ZIP or GitHub link without ever running it, and looks for the tricks that make code execute the moment you open, install or build it. Each finding comes with the file, the line and a plain-English reason, and everything rolls up into a Safe, Suspicious or Dangerous verdict with a 0–100 risk score.

03 / The problem

Opening a folder should not be enough to get you hacked.

Fake recruiters send developers “take-home tests” that hide malware in places that run automatically: editor tasks that fire when a folder opens, install hooks, git hooks and download-and-run scripts. Most people never look in those places before they trust a project.

    Code that runs the moment a folder is opened

  2. 02

    Install and git hooks that hide in plain sight

  3. 03

    No quick way to check before you click “Trust”

04 / How it works

Read safely, scan, score, explain.

  1. 01

    Ingest

    Reads a folder or ZIP into memory with size, file and depth limits, and rejects zip bombs and zip-slip.

  2. 02

    Scan

    11 rules look for folder-open tasks, install hooks, hidden git hooks, download-and-run scripts, obfuscation and typosquats.

  3. 03

    Score

    Findings roll up into a Safe / Suspicious / Dangerous verdict and a 0–100 risk score.

  4. 04

    Explain

    Every finding points to a file and line with a plain-English reason.

  5. 05

    Surface

    One engine behind a CLI, a VS Code extension, a web app and a Chrome extension.

05 / Key decisions

Where the important calls were made.

Decision 01

Should it run the code to see what it does?

  1. →

    The choice

    Never. Static analysis only, and no git clone: repos are fetched as archives.

  2. →

    What it gave

    It is safe to point at hostile input, which is the whole point.

Decision 02

How do you avoid crying wolf?

  1. →

    The choice

    Suspicious-only repos are capped below the Dangerous range, and every rule is tested against popular projects.

  2. →

    What it gave

    Normal install scripts never look like a real trap.

Decision 03

One tool or four?

  1. →

    The choice

    One scanning engine shared by the CLI, VS Code, the web app and the browser extension.

  2. →

    What it gave

    The same verdict wherever a developer meets the repo.
